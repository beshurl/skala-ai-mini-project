# 프론트 화면 적용

루트 DESIGN.md와 src/styles/tokens.css가 공통 기준이다. 이전 네이비·바이올렛 팔레트는 사용자 요청에 따라 차콜·웜 골드·아이보리로 대체한다.

랜딩(Persuade/Experience): 제공된 문·기록실·탐정 장면을 유지한다. 중앙 제목과 시작 버튼을 명확히 하고 한글 본문 가독성을 높인다. 공개된 자료의 관계를 검토하는 서비스라는 사실과 합성 체험 범위를 쓴다.

사건(Operate): /cases 기록 목록의 읽기 순서는 제목 → 실제 사건 수/검색 → 기록 목록 → 검토 방법. 세부 화면은 사건 탐색 → 제목/버전 → 분석/공개 원문 → 비교/이력. 1120px 이하 탐색을 상단으로, 800px 이하 원문·분석을 한 열로 전환한다.

이력/실행 정보(Operate/Read): 공통 헤더·페이지 제목·기록 행·정보 표로 구성한다. 관리자(Operate): 같은 토큰과 브랜드를 쓰되 실측 지표/표/필터의 밀도를 유지한다. 로그인/회원가입은 AuthView.vue에서 같은 토큰·BrandMark·폼 조작부를 공유한다. 데스크톱은 소개/폼 두 열,800px 이하는 폼 한 열이다.

상태는 텍스트로 반복하고 미측정을0으로 대체하지 않는다. 표는 영역 내부 스크롤, 폼44px, focus-visible2px, 최소320px 폭을 지원한다. 네트워크/권한/소유권 계약과 실제 API 응답을 바꾸지 않는다.


2026-10-20 사용자 후속 요청: `/cases`의 AI 생성 템플릿 같은 인상을 줄인다. 기록 목록에는 대형 슬로건·장식 R·영문 카피·가짜 문서 번호를 두지 않는다. 작은 페이지 제목, 검색, 실제 사건 제목/요약/증거 버전을 우선한다. 첫 입장과 빈 분석 상태도 설명 중심 문장으로 쓴다. 메인의 제공 연출과 공통 브랜드/색상은 유지한다.


2026-10-20 구분선 후속: `/cases`의 선은 목록의 열 제목 아래와 서로 다른 기록 사이에만 둔다. 문구·모델 정보·버튼 그룹은 여백으로 나눈다. 제목/요약/증거 버전/열기 열은 같은 시작선에 정렬한다. 검토실은 수직 분할선을 없애고 원문 패널의 면과 열 간격으로 구분한다. 인용 포커스·의미 상태·조작부 경계는 기능에 필요한 범위에서 유지한다.


2026-10-20 서비스 정체성 정정: 중심 설명은 “증거 기반 AI 미제사건 재수사 지원”이다. 합성 사건은 현재 체험/검증 데이터의 범위로 표시한다. 목표 기능과 현재 검증 범위를 구분하며 실제 사건 성능·운영 검증을 완료했다고 쓰지 않는다.
