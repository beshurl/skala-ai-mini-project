# 판단 계약과 경계 사례

핵심 흐름: 명시적 로컬 데모 입장 → 사건 선택 → 공개 증거 확인 → 분석 작업 생성 → 실제 SSE 상태 → 근거 원문 확인 → 새 증거 공개 → 새 버전 재분석 → 결과 비교.

## 라벨

| 서비스 라벨 | 기존 모델 라벨 | 판정 기준 | 반례/주의 |
|---|---|---|---|
| SUPPORTED | 일치 | 검토하는 주장과 공개 자료가 양립하고 자료가 그 관계를 뒷받침함 | 일부 시각/장소 일치만으로 진술 전체가 사실이라는 뜻 아님 |
| CONTRADICTED | 모순 | 동일 대상·사건·조건에 관한 명시적 진술과 확인된 기록이 충돌함 | 두 진술이 다르다고 거짓말한 사람을 확정할 수 없음 |
| INSUFFICIENT | 추가확인필요 | 판단에 필요한 전제·식별·기록이 부족함 | 미관측을 부재 증명으로, 낮은 신뢰도를 유죄 확률로 변환하지 않음 |

서비스 결과는 Pydantic `AnalysisResult/Finding`으로 검증하며 JSON Schema는 `schemas/analysis_result.schema.json`. case_id/version은 서버가 지정한다. 모델이 선택한 근거는 현재 검색 결과와 공개 스냅샷에 있어야 한다. 결과의 rationale은 짧은 외부 검증 가능 근거이고 내부 사고과정은 저장/표시하지 않는다. 가설은 검증 가능한 내용이 없으면 빈 배열로 유지하고 화면에서 명시한다.

현재 데모는 방문 부정 진술의 관계 분석으로 범위를 제한한다. 문서의 전체 사실 추출, 실존 인물 판단, 복잡한 가설 생성 기능은 검증하지 않았다. 판례는 참고 문서이며 현재 사건 사실을 입증하는 증거로 사용할 수 없다.

## 시간과 장소

- 기록은 timezone-aware 시각으로 표현하고 Asia/Seoul 표시, 날짜 경계와 시계 오차를 보존한다.
- 순간 관측과 연속 체류 주장을 구분한다. 두 관측 사이에 계속 있었다고 추정하지 않는다.
- 장소가 다르더라도 검증된 최소 이동시간이 없으면 불가능을 확정하지 않는다.
- 동일인 식별이 불확실하면 위치 충돌을 인물의 모순으로 확정하지 않는다.
- `recase/temporal.py`는 순간 관측의 시간적 양립 가능성만 판정하는 독립 규칙 기준선이다. POSSIBLE은 실제 방문/주장 전체를 입증하지 않는다.
- 예: 21:00 연구실/21:05 주차장, 이동시간 불명=INSUFFICIENT. 최소12분/오차0=IMPOSSIBLE. 최소7분/각±90초=INSUFFICIENT. 날짜 변경/시간대 변환은 실제 datetime 차이를 사용한다.

정상·충돌·정보 부족·시간 오차·날짜 경계·동일인 불확실성은 tests/test_temporal.py와 서비스 테스트에서 검증한다. 이는 규칙/통합 검증이며 모델 일반화 측정이 아니다.
