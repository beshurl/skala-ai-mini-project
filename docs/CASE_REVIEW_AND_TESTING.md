# 미제사건에서 RE:CASE가 해야 하는 일과 직접 테스트하는 방법

현재 소스·합성 미리보기 기준, 2026-10-21. 실제 미제사건 원문을 수집하거나 모델에 전송하지 않았다.

## 해결되지 않은 사건에서 AI가 도울 수 있는 범위

자료를 많이 읽었다는 것만으로 과거에 없던 증거가 생기지 않는다. RE:CASE의 목표는 자료를 출처와 시점에 맞게 정리하고, 서로 충돌하는 주장과 빠진 정보를 찾아, 다음 사람이 확인할 항목을 분명하게 남기는 것이다. 범인을 지목하거나 유죄 확률을 제시하는 기능은 만들지 않는다.

NIJ의 미제사건 검토 안내도 기존 사건 파일·증거의 재검토, 새로운 정보와 감정 방법의 검토, 여러 분야 전문가의 참여를 강조한다. 이는 일반적인 검토 방향을 참고한 것이며 대한민국 수사·재판의 법적 절차를 대체하는 안내가 아니다. [NIJ 미제사건 검토 안내](https://nij.ojp.gov/index.php/topics/articles/expert-panel-issues-new-best-practices-guide-cold-case-investigations).

LLM은 근거가 부족한 상황에서도 그럴듯한 설명을 만들어낼 수 있다. 따라서 설명의 유창함 대신 원문 인용·누락 정보·반대 근거·자료 범위를 확인해야 한다. [NIST 생성형 AI 위험 프로필](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf).

## 결과와 대응을 구분하는 법

| 관측된 상태 | 적절한 설명 | 다음 확인 | 해서는 안 되는 결론 |
| --- | --- | --- | --- |
| 주장과 자료가 일치 | 현재 제공된 자료는 해당 주장을 지지한다 | 원본·범위·독립 출처·반대 자료 확인 | 그 사람이 범인이다/사건 해결 |
| 주장과 자료가 충돌 | 두 진술 또는 기록의 내용이 양립하기 어렵다 | 신원·날짜·시계 오차·정정·출처 신뢰성 확인 | 고의로 거짓말했다/유죄다 |
| 증거 부족 | 어떤 사실이 빠졌기 때문에 관계를 판단할 수 없다 | 필요한 자료의 종류·담당자·존재 여부 확인 | 기록이 없으니 방문하지 않았다 |
| 출처끼리 충돌 | 서로 다른 자료의 검사 조건·범위가 확인되지 않는다 | 원자료·검사 조건·보관 이력을 전문가가 검토 | 다수결로 한쪽을 정답 처리 |
| 자료 검색·구조 검증 실패 | 도구나 모델이 유효한 비교 결과를 만들지 못했다 | 오류 원인·검색 범위·원문·형식 점검 | 실제 사건의 증거가 없다고 해석 |
| 반대 증거·정정 발견 | 이전 판단의 범위나 근거를 수정해야 한다 | 과거 결과를 보존하고 변경 이유·새 인용 기록 | 이전 결과를 지우거나 유리한 자료만 선택 |

‘모른다’는 답에는 최소한 **모르는 대상·현재 확인된 사실·빠진 정보·확인 방법·재검토 조건**이 있어야 한다. 추가 확인 요청은 제안이며 실제 조사·검사·공문 요청을 실행했다고 적지 않는다. 자료를 확보할 수 없으면 보류 상태와 이유를 남긴다.

### 예: 봉인 서류함 분실

1. A는 보관실에 안 갔다고 말한다. 출입 장치에는 누군가의 통과 흔적만 있다. → **A인지 모르므로 추가 확인 필요**.
2. 원기록 대조로 그 통과자가 A임을 확인한다. → **방문 부인 진술과 출입 기록은 충돌**.
3. 안내등 점검 기록이 추가된다. → **방문 관련 판단은 유지**. 무관한 자료가 늘었다고 확신을 높이지 않는다.

이 경우에도 **누가 서류함을 옮겼는지, 승인된 이관이었는지, 실제 분실이 언제 발생했는지는 모른다**. 필요한 다음 자료는 반출·이관 기록과 확인 가능한 물품 이동 자료다. A의 방문과 서류함 반출은 서로 다른 주장이다. 세 단계 모두 사건 자체는 미해결 상태다.

## 현재 구현된 범위

최신 소스에는 [다중 증거 검토 경로](GENERAL_REASONING.md)가 추가됐다. 직접 가상 사건을 작성하거나 ‘다중 증거 검토용 사건12개 추가’를 선택하면 전체 공개 자료와 주장을 함께 검토하고 원문/가설/다음 확인을 표시한다. 원문 구간 검증은 의미 정확도의 증명이 아니다. 실제 모델의 시간 구간·동명이인·검사 충돌·정정/전언 판단 품질은 NOT_RUN이다.

기존 ‘테스트 사건3개’와 저장된 이력은 legacy 방문 대조 경로로 보존한다. 아래9단계 결과는 이 경로의 고정 모의 응답이다. localhost:8123 미리보기와 실제 UID499/8100에 최신 변경을 자동 적용하지 않았다. 최신132파일 후보는 미배포이며 이번 브라우저 검증은 별도8139의 가상 상태/FixtureModel만 사용했다. 연습 참고표/실제 정답은 모델 입력이 아니다.

## 바로 실행할 앱 테스트3개

1. [회원가입](http://localhost:8123/signup) 또는 [로그인](http://localhost:8123/login)한다.
2. [사건 기록](http://localhost:8123/cases)에서 **테스트 사건 3개 추가**를 누른다. 다시 눌러도 기존 증거 버전·분석 이력을 초기화하거나 사건을 중복 생성하지 않는다. 기존 사건도 그대로 남는다.
3. 사건을 열고 공개 증거를 읽는다. **현재 증거로 분석** → 근거 인용 확인 → 다음 증거 공개 → 재분석을 진행한다. 새 자료는 두 번 공개할 수 있다.
4. 비교할 이전 분석을 선택해 **결과 비교**를 누른다. 정답 참고표를 보기 전에 본인 판단과 빠진 정보를 먼저 기록한다.

| 사건 | v1 → v2 → v3에서 확인할 관계 | 현재 실행 상태의 의미 |
| --- | --- | --- |
| P01 봉인 서류함 분실 | 추가 확인 필요 → 자료 간 충돌 → 충돌 유지 | 신원 확인 후 방문 진술을 재검토; 반출자는 모름 |
| P02 전시 기록함 분실 | 추가 확인 필요 → 추가 확인 필요 → 추가 확인 필요 | 유사한 옷·날씨로 신원을 확정하지 않음 |
| P03 구관 장부 분실 | 추가 확인 필요 → 추가 확인 필요 → 추가 확인 필요 | v1/v2는 같은 날짜의 비교 기록 부족으로 부분 완료, v3는 신원 미확인 |

**‘분석 완료’는 실행이 끝났다는 뜻**이다. `COMPLETED + INSUFFICIENT`는 자료를 비교한 뒤 보류한 결과이고, `PARTIAL + RETRIEVAL_INSUFFICIENT`는 현재 비교 범위에서 관련 자료가 부족하다는 실행 상태다. 후자를 사건 전체에 증거가 없다는 판단으로 확대하지 않는다. 실패·누락·무효 응답도 테스트 기록에 남긴다.

## 자료 묶음 전체

- 가상 사건12개, 문서48개, 공개 단계36개.
- P01~P03: 현재 앱에 연결한 제한된 합성 기능 테스트9단계.
- P04~P12: 새 다중 증거 경로에 명시 추가할 수 있는27단계. 실제 모델 의미 성능·통과 판정은 NOT_RUN이다.
- `cases.json`: 입력 원문/출처/공개 단계. `snapshots.jsonl`: 각 단계까지 공개된 자료만 포함한36개 입력. 평가 참고나 이후 단계의 문장은 넣지 않는다.
- `review_reference.json`, `검토참고표.md`: AI가 작성한 **검수 대기 제안**36개. 사람 검수 완료 정답/독립 최종 평가 자료가 아니다.
- `결과기록.json`, `결과기록.md`: 사용자용 빈 기록지. 처음에는 모든36단계가 NOT_RUN이고 시간/점수는 NOT_MEASURED다.
- `사건별/`:12개 사건의 단계별 읽기 자료. 자동 연결이 없는 사례도 바로 읽고 판단/근거/확인 요청을 작성할 수 있다.
- `manifest.json`: 파일 SHA256/출처/범위. `exposure_log.json`: AI 작성·검토 노출/비학습·비최종 상태. 기존 NLI 동결/노출 ledger와 혼합하지 않는다.

각 단계에서 관측한 관계, 실제 인용 원문, 누락 정보의 구체성, 근거 없는 단정, 반대 증거 이후 판단 갱신 여부를 기록한다. 원문을 확인하지 못했거나 앱이 실패했으면 분모에서 빼지 않고 실패/미실행으로 남긴다. 이 묶음은 비슷한 방문 대조 구조를 포함하므로12건을12개 독립 계열로 세지 않는다. 데이터 양을 늘려 독립성을 확보했다고 주장하지 않는다.

## 실제 데이터와 학습으로 나아가는 순서

1. 우선 이번 합성 자료로 기능과 실패 상황을 확인한다. 실명·주소·신분증·실제 사건 원문을 넣지 않는다.
2. 실제 사건에서는 사용 권한·이용 목적 승인·비식별화·사람 검수·출처와 보관 이력을 확보한다. 현재 격리 원문은 그대로 유지한다.
3. 실제 미제사건에는 범인 정답이 없을 수 있다. ‘해결률’을 임의로 계산하지 말고 근거 인용의 정확성·누락 정보 탐지·잘못된 단정·새 증거 갱신을 먼저 검토한다.
4. 해결된 사건으로 검토하려면 해결 이전/이후 자료를 시간별로 분리하고, 학습에 노출되지 않은 검증용 사건 계열과 전문가 제안 기준을 별도로 확보한다. 공개 여부만으로 사전학습 노출이 없다고 보장할 수 없다.
5. 검수된 데이터에서 설정을 고정하고, 현재 OS 정답 접근 차단·공유 모델 잠금·기존 최대3후보 gate를 통과한 뒤에만 실제 모델 평가/학습을 한다. 이번36개 제안 기준을 그 조건 대신 사용하지 않는다.

재수사를 진전시키는 현실적인 결과는 ‘범인을 자동으로 찾았다’는 문구가 아니라 **검토 가능한 새 단서·정정된 잘못된 연결·명확해진 자료 공백·근거 있는 다음 확인 요청**이다.
