# 평가 프로토콜 v2 (실험 전 고정)

2026-10-20 KST. 기존 test.jsonl은 결과가 이미 노출된 **개발 평가셋**이다. 최종 블라인드 성능을 주장하지 않는다.

평가 단위는 case_id로 식별되는 두 자료 관계 1건. 라벨은 기존 계약 `일치`, `모순`, `추가확인필요`를 보존하며 서비스의 SUPPORTED/CONTRADICTED/INSUFFICIENT와 매핑한다.

- 일치: 같은 사실을 확인하는 자료. 시간·장소가 같다는 것만으로 유죄나 진술 전체의 진실을 의미하지 않는다.
- 모순: 동일 전제·대상·시점의 명시적 부정과 확인된 기록이 충돌. 어느 진술자가 거짓말했는지 확정하지 않는다.
- 추가확인필요: 시각 오차, 이동시간, 장소 관계, 동일인 식별 등 필수 전제가 부족. 두 장소 기록만으로 물리적 불가능을 단정하지 않는다.
- 시각은 Asia/Seoul로 명시하고 날짜 경계·오차 범위를 보존한다. 미관측은 부재의 증명이 아니다. 판례는 현재 사건 사실의 증거가 아니다.

필수 응답은 JSON 객체 `label`, 비어 있지 않은 `reason`, 중복 없는 `evidence_ids` 목록이다. 존재하고 현재 접근 가능한 ID만 허용한다. 일치/모순에는 적어도 하나의 근거가 필요하다. 추가확인필요도 인용 ID를 검증한다.

주 지표는 고정 3클래스 Macro F1. accuracy, 클래스별 P/R/F1, 원시 JSON 성공률, 복구 후 성공률, 인용 유효율, invalid_rate, 보류 precision/recall, p50/p95/평균 지연, 입력/출력 토큰, 모델 호출 수, MLX peak allocated memory를 보조 지표로 기록한다. MLX 수치는 시스템 전체 메모리가 아니다.

빈 출력·잘린 출력·필수 필드 누락·금지 ID·중복 case_id·누락 예측은 invalid로 평가하며 전체 정답 수를 분모로 쓴다. 알 수 없는 예측 ID는 integrity error로 기록하고 실행을 유효 비교에서 제외한다. 실패를 삭제하지 않는다. 정답 증거 선택/가설 갱신/근거의 의미적 정확성은 별도 검수셋 없이는 NOT_MEASURED다.

복구는 정확히 하나의 완결된 JSON 코드펜스 또는 완결된 think 블록 제거 1회만 허용한다. 추측 라벨 추출·JSON 문법 보정·추가 LLM 호출은 하지 않는다. raw와 recovered를 별도 기록한다.

Base/FT는 같은 snapshot revision, 데이터 bytes hash와 sample ID 순서, system prompt, thinking=False, greedy(temp=0), seed=0, max_tokens=256, 평가기 버전을 쓴다. 다른 조건은 비교 거부한다. 어댑터 경로/해시와 실제 LoRA 모듈 수를 기록한다. 표본 54건 전체를 사용한다. 후속 모델 선택은 검증셋으로만 하고 개발 평가 결과에 맞춰 프롬프트를 변경하지 않는다.

기존 어댑터의 재현 확인이 이번 목적이며 학습 후보는 0개 사용한다. Base·FT 각 1회(장애 원인 수정시 1회 추가), 메모리 압박 또는 시스템 불안정시 중단. 예상 평가 시간 합계 3~10분, 기존 캐시만 사용하며 네트워크 다운로드는 하지 않는다.

시연 채택 기준: 계약/권한 테스트 통과, 실제 어댑터 적용 확인, 실패를 명시하는 동작. 합성 점수만으로 실사용 모델 승격은 하지 않는다. 작은 점수 차이보다 단순성·지연을 우선하되 의미적 오류를 속도로 상쇄하지 않는다. 블라인드 평가·독립 시나리오·사람 검수가 확보되기 전 PILOT_READY/PRODUCTION_READY 승격 금지.
