# 사건별 증거 기반 대화

현재 기능 브랜치 `back/feature/recase-case-conversation`의 구현이다. 합성 자료·모의 모델로 API와 화면을 검증했다. 실제 MLX 대화 품질은 NOT_RUN/NOT_MEASURED이며 실제 UID499 운영에는 반영하지 않았다.

## 사용 방법

로그인 → 사건 기록 → 사건 선택 → **사건에 질문하기**에서 질문을 보낸다. Enter는 전송, Shift+Enter는 줄바꿈이다. 한국어 입력 조합 중 Enter는 전송하지 않는다. 답변의 원문 버튼은 해당 증거의 정확한 인용 구간으로 이동한다. ‘이어서 물어보기’는 질문 초안만 채우며 사용자 전송 전에 모델을 호출하지 않는다.

예: “공개 자료 사이에 충돌하는 내용이 있나요?”, “이 진술을 확인하려면 어떤 자료가 더 필요한가요?”, “새로 공개된 기록으로 무엇이 달라졌나요?”

사건마다 전체 대화를 서버에 저장하며 20개씩 이전 기록을 불러올 수 있다. 현재 답변에는 같은 사건에서 답변이 완료된 최근 대화 최대 3개만 참고한다. 문맥이 부족하면 오래된 대화를 통째로 줄이고 사용한 대화 ID와 제외 수를 기록한다. 현재 공개 증거를 조용히 잘라 내지 않으며 증거만으로도 문맥을 넘으면 처리 한도 오류를 표시한다. 이전 답변과 사용자 질문은 증거로 취급하지 않는다.

새 증거 공개 후에도 이전 답변을 고쳐 쓰지 않는다. 이전 대화에 당시 증거 버전을 표시하고 새 질문에는 현재 공개 자료를 사용한다. 근거 부족은 `INSUFFICIENT`, 모델·입력·인용 검사 실패는 `PARTIAL/UNAVAILABLE`로 구분한다. 검사에 실패한 모델 원문을 화면이나 로그에 공개하지 않는다.

## 처리·저장 경계

- GET/POST `/api/cases/{case_id}/conversation`. 인증·소유권·동일 출처·CSRF·질문 1,500자·현재 증거 버전·마지막 대화 ID를 서버에서 확인한다. 임의 messages/role/도구·권한 필드는 허용하지 않는다.
- 대화는 별도 종류의 기존 `jobs`에 질문·불변 공개 자료·최근 대화와 함께 저장한다. 새 DB 스키마/테이블이나 자동 migration을 도입하지 않는다. 기존 전체 분석 목록/비교에서는 대화를 제외한다.
- 기존 단일 Worker/대기열/모델을 공유한다. 질문 하나에 모델 호출 최대 1회·출력 1,024토큰·작업 한도 180초·모델 재시도 0회다. 취소·서버 재시작·대기열 제한을 재사용한다.
- 모델에는 서버 권한으로 stdio MCP에서 다시 확인한 현재 공개 자료만 전달한다. 미공개 증거·평가 정답·판결문 격리 원문·API 키·세션은 전달하지 않는다. 모델이 도구나 권한을 선택하지 않는다.
- 답변의 각 설명 문단에는 현재 증거의 인용이 필요하다. 원문 ID·연속 문자열·Unicode 시작/끝 구간을 서버에서 검사한다. 형식 정리는 최대 1회이며 별도 모델 복구 호출은 없다. 범인/유죄 단정 서술을 거부한다. 인용 검사는 의미 정확도의 증명이 아니다.
- 각 전송은 요청 ID와 내용 fingerprint에 묶인다. 동일 요청의 재확인은 기존 작업을 돌려주며 새 모델 작업을 추가하지 않는다. 네트워크/5xx 불확실성에는 질문 초안과 원래 요청 ID를 메모리에 보존한다. 자동 POST 재시도는 없으며 사용자가 새로고침 또는 ‘같은 요청 확인하기’를 선택한다. 브라우저 새로고침/페이지 이탈 전의 미전송 초안을 영구 저장하는 기능은 없다.
- 질문과 답변은 같은 사건의 보존·암호화 백업 대상이다. 사건 삭제와 최신 독립 journal 재적용은 대화 jobs/events도 제거한다. 과거 백업 파일의 물리적 완전 삭제를 보장하지 않는다. 별도의 대화 로그/질문 원문 tracing은 없다.

## 검증

고유 run `20261021T102531+0900-case-conversation-b79dc2`의 `backend-tests.json/log`: 전체 **285 tests PASS**. 프론트 `frontend-final-checks.json`: **22 tests·typecheck·build PASS**, 후속 문구 수정은 `frontend-copy-final.json`의 타입/빌드로 확인한다. 새 대화 검증은 백엔드 13개·프론트 6개다.

합성 검사 범위: 후속 맥락·현재 공개 자료·인용·잘못된 인용/범위/단정 거부·타인/CSRF·엄격한 입력·동일 요청 재확인·동시 분석 차단·취소/증거 변경·재시작/백업·20개 cursor/최근3개/문맥 축소·사건 삭제/최신 journal 재적용·네트워크 불확실성·늦은 다른 화면 응답 거부다. 실제 모델 성능이나 수사 정확도 측정이 아니다.

실제 브라우저에서 합성 계정의 질문/후속 질문/Enter·원문 이동·v1→v2 후 이전 버전 표시·저장 이력을 확인한다. 모바일·데스크톱 결과와 캡처는 같은 run에 보관한다. 새 모의 미리보기는 8131 포트·새 DB/journal·별도 쿠키 이름으로 기존 운영과 분리한다. 공유 테스트 비밀번호는 실제 계정에 사용하지 않는다.

## 메인 반영 전

원본 프로젝트에는 결과 수신/취소 전 평가 계획에 묶인 backend 소스를 고정하는 AGENTS 규칙이 있다. 이 브랜치는 별도 worktree에서 구현했으며 원본 소스·UID499 서비스·모델 잠금/어댑터·데이터·기존 평가 계획은 수정하지 않았다. 기존 평가를 완료하거나 명시적으로 취소한 뒤 변경을 통합하고 필요한 실행 계획을 새 소스 해시에 다시 결합해야 한다. 옛 `--execute`를 그대로 실행하거나 이 worktree에서 실제 모델/학습을 중복 시작하지 않는다. 실제 배포에는 기존 공유 루트·독립 journal·계정/정답 OS·모델 단일 실행 요건을 계속 적용한다.
