# 메인·사건 화면 디자인 통합

2026-10-20 KST. 사용자가 디자인 시스템 전체 통일과 `/cases`·메인의 전면 수정을 요청했다. 구현 범위는 프론트 소스와 로컬 모의 모델 미리보기다. 전체 서비스/실제 사건 성능 판정은 바꾸지 않는다.

## 반영

- `frontend/src/styles/tokens.css`: 차콜·웜 골드·아이보리, 의미 상태색, 시스템 한글 글꼴, 모서리·간격을 공통 정의한다. `system.css`는 버튼·초점·건너뛰기·44px 조작 기준을 담당한다.
- `BrandMark`, `SiteHeader`, `ModelDetails`로 브랜드·메뉴·모델 정보 중복을 줄였다. 로그인은 독립 HTML/CSP를 유지하며 빌드 전 토큰과 `auth.css`를 결합한다. 접근키·권한 계약은 변경하지 않았다.
- 메인: 제공된 문·기록실·탐정·증거 보드·캐러셀 자산과 애니메이션을 유지한다. 중앙 시작 버튼·설명·제목 위계와 본문 가독성을 높이고 공통 헤더·버튼·다이얼로그 색을 적용했다.
- `/cases`: 검색 가능한 기록 목록으로 분리했다. 실제 사건 제목·요약·증거 버전을 표시하며 명시적인 데모 입장/새 데모 생성과 빈 검색 결과를 구분한다. 방문만으로 새 데모를 만들지 않는다.
- `/cases/:id`: 분석과 원문을 나란히 두고 모바일에서는 공개 증거 다음 분석으로 읽는다. 바로가기로 두 영역을 이동할 수 있다. 라벨·원문 인용·실제 진행·취소/오류·버전 차이·비교·이력을 재구성했다. 비교 근거는 넓은 화면에서 이전/현재 두 열로 표시한다.
- 이력·실행 정보·관리자8개 화면·개인 로그인도 같은 색상과 브랜드를 사용한다. 관리자 표의 내부 스크롤과 실제 통계 정의는 유지한다.

## 검증

근거 폴더: `outputs/runs/20261020T154203+0900-design-unification/`.

- `final-checks.json`: 명령·시각·종료코드. `npm run typecheck`, `npm test` 5/5, `npm run build`, `git diff --check` 모두 exit0.
- `browser-desktop.json`, `browser-mobile.json`: **명시적 fixture**에서 새 합성 데모 → 미공개 증거 비노출 → v1 추가 확인 필요 → v2 충돌/원문 인용/판단 변경 → v3 무관 자료/판단 유지 전체 흐름 PASS. 실제 MLX 추론 성능 검증이 아니다.
- `browser-extras.json`: 검색·초기화, 첫 입장, 이력의 v1 선택/현재 v3 경고, 카드 상세/Escape/다음 카드, 관리자 로그 표 확인. 320px 사건 목록/검토실과390px 목록/검토실/실행 정보/관리자에서 가로 넘침 없음. 관찰한 검토실의 표시 버튼은 모두44px 이상이다.
- `contrast.json`: 공통 텍스트/배경 역할의 최소 대비7.97:1. 이미지 위 모든 위치의 픽셀 대비를 자동 보증하는 결과는 아니며 랜딩은 직접 시각 점검했다.
- `design-detector.json`: 소스 정적 검사1회, 발견0. 별도 검토 에이전트 없이 이 대화에서 직접 데스크톱·모바일 화면을 최종 검수했다. 기록실 첫 화면에서 다음 사건도 보이도록 제목 영역과 행 간격을 조정했다.
- `preservation.json`: 기존 데이터/어댑터/평가14개, 제공 이미지12개 보존. 이전 검증의 backend 소스 해시 동일. API·모델·인증·운영 DB·보호 볼륨 변경 없음.
- 스크린샷: `landing-{desktop,mobile}.png`, `cases-{desktop,mobile}.png`, `workspace-{desktop,mobile}.png`, `entry-{desktop,mobile}.png`, `admin-{desktop,mobile}.png`, `login-mobile.png`.
