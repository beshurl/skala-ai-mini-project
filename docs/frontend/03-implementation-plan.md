# 단계별 구현 계획

1. 기반: 경로·사용자/운영자 레이아웃, types/api.ts, 오류/취소/15초 timeout. 읽기 재시도는 명시적 수동, 쓰기/LLM 자동 재시도0. vue-tsc/build/Node API client tests 후 다음 단계.
2. 랜딩: 제공 RECASE HTML을 Vue로 분리;14개 이미지는 해시 보존 추출. 수식/장면/캐러셀 유지, inert 및 애니메이션 정리 추가. 작업실은 기존 기능 그대로 별도 경로. 빌드 및 CUA desktop/mobile 확인.
3. 운영 관측: 독립 관리자 인증/세션/CSRF/로그인 rate 제한. 기존 DB에 스키마 변경 없이 별도 안전한 SQLite 이벤트. HTTP/LLM/MCP/keyword 계측은 성능/결과 계약을 바꾸지 않는다. 기존96 tests와 신규 보안/기록/실패 테스트 후 다음.
4. 관리자 화면: 개요/필터 가능한 기록/요청/모델/검색/도구/오류/시스템; 샘플 수와 미수집 명시. 실제 fixture API+stdio 통합 브라우저 검증.
5. 최종: 검증 결과/실행 명령/성능 표본/보안·운영 교체 제한 기록. 기존 산출물14해시 확인. UID499 서비스 재시작/모델 중복 로드/실제 정답 읽기/학습은 수행하지 않는다. 실제 MLX 전체 신규 UI 검증이 아직 안 되면 NOT_RUN으로 남긴다.

변경 이유: 현재 단일 화면은 랜딩/권한 별 운영을 표현할 수 없고 요청/실패 계측이 없다. 새로운 SaaS/로그 인프라 없이 기존 Vue/FastAPI를 확장하는 최소 범위를 선택했다. 별도 서비스 배포 사본이므로 개발 결과가 운영에 자동 적용되었다고 보고하지 않는다.
