# Git 작업 안내

원격 저장소: https://github.com/beshurl/skala-ai-mini-project

`main`은 프론트/백엔드와 문서·합성 자료를 포함하는 통합 기준 브랜치다. 기능 브랜치는 `back/feature/<작업-설명>` 형식으로 만든다. 예: `back/feature/recase-auth-evidence-data-pipeline`. 브랜치명에 `codex`를 넣지 않는다. 새 기능/수정 커밋 제목은 `[fe]feat: <구현·수정 내용>` 형식을 사용하며 기존 커밋의 메시지·작성자·이력을 임의 재작성하지 않는다.

전체 변경 게시를 요청받으면 미추적 소스도 확인해 검증·커밋하고 기능 브랜치에서 `main`으로 병합한다. 사용자가 브랜치 동기화도 요청한 경우 관련 기능 브랜치를 병합 결과로 fast-forward한다. 원격과 로컬 SHA·브랜치 간 diff·작업 폴더의 변경/미추적 파일이 없는지 확인한다. 실행 중인 로컬 서비스를 중단하거나 소스가 과거 버전으로 잠시 바뀌는 checkout을 하지 않도록 동일 트리의 병합 또는 별도 검증 사본을 사용한다. clean 상태를 만들기 위해 실제 자료를 삭제하거나 제외 규칙으로 소스 변경을 숨기지 않는다.

## 저장소에 포함하는 파일

- 프론트/백엔드 소스·테스트·의존성 선언과 lock 파일
- 화면에서 실제 사용하는 이미지와 정적 자산
- 환경변수 예시, 권리/학습 설정 예시와 정적 운영정책 명세
- 명시적인 합성 연습자료 `data/practice/v1/cases.json`과 분리된 AI 제안 참고표
- 구현 범위·실행 방법·검증 한계를 설명하는 문서

합성 연습자료/제안 참고표는 사람 검수 완료·학습 승인·독립 최종셋을 뜻하지 않는다.

## 업로드에서 제외하는 파일

`.gitignore`는 환경변수 실제 값·인증정보·개인키, SQLite/계정 DB/WAL, 삭제 journal과 검수 ledger, 실제 수집 원문·전처리 자료, 모델 가중치·어댑터·체크포인트, 실행/평가/백업 산출물, 가상환경·node_modules·빌드·브라우저/테스트 보고서와 로컬 디자인 메모를 제외한다. data/는 기본 제외하고 명시적인 정적 파일만 허용한다.

공개 사건 원본은 프로젝트 밖 개인 데이터 저장소에 남긴다. 원문을 코드 저장소나 프론트 정적 자산으로 옮기지 않는다. `git add -f`로 제외 규칙을 우회하지 않는다. 비밀값이 이미 추적된 경우 `.gitignore` 추가만으로 과거 커밋에서 지워지지 않으므로 푸시를 멈추고 해당 범위를 별도로 처리한다.

## 검증

기존 데이터와 운영 서비스를 건드리지 않도록 Git 대상 소스만 별도 사본으로 복사해 백엔드 테스트와 프론트 테스트·타입 검사·빌드를 수행한다. 프론트 의존성은 lock 파일 기준으로 설치한다. 원격에 올릴 파일과 검사한 소스의 SHA256을 대조하고 과거 이력·최종 커밋의 비밀값 검사를 수행한다.

데이터 감사 테스트는 공개 합성 생성기로 임시 폴더에 자료를 만들며 `data/processed/`를 요구하거나 수정하지 않는다. 실제 토크나이저 통합 테스트는 기존 로컬 Qwen 캐시가 있을 때만 수행하고 캐시가 없으면 이유를 명시해 건너뛴다. 모델을 자동 내려받거나 학습·추론을 실행하는 검증이 아니다.

소스·합성 테스트의 통과는 실제 MLX 품질·실제 사건 정확도·운영 배포 승인을 뜻하지 않는다. 실제 자료는 별도 목적별 검수·권한·OS 격리·모델 잠금·학습 주기 gate를 계속 따른다.
