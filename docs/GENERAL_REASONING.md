## 사용하는 방법

최신 소스/빌드의 사건 기록실에서 ‘새 가상 사건 작성’을 열어 주장과 자료를 입력한다. ‘처음부터 공개’를 해제한 자료는 나중에 ‘새 증거 공개’로 하나씩 공개한다. 저장 뒤 분석 → 원문 구간 열기 → 가설/다음 확인 → 새 증거 공개/재분석 → 이전 결과 비교 순서로 확인한다. 원문 인용 구간으로 이동하며 키보드 포커스도 해당 구간에 둔다. 오류가 나면 작성 초안을 유지한다. 같은 작성 요청의 재전송은 동일 사건을 반환하며 내용이 달라지면 충돌을 거부한다.

‘다중 증거 검토용 사건12개 추가’는 기존3개 방문 대조 연습과 구분된 새 사건을 만든다. 반복 추가는 버전/이력을 지우지 않는다. P04~P12도 이 경로에 연결되지만 실제 모델의 정답 통과를 뜻하지 않는다. AI 작성 참고표는 서비스/프롬프트/후보 패키지에서 제외한다. 직접 입력은 가상 자료라는 사용자 확인을 요구하며 이 확인을 검수·권리·학습 승인으로 바꾸지 않는다. 실제 판결문 반입/표시/검색 승인은 별도다.

## 분석 계약과 한계

서버가 현재 사용자/사건 버전의 공개 snapshot을 확정한다. 날짜/장소가 다르다는 이유로 자료를 버리지 않으며 주장과 모든 공개 자료를 함께 모델에 보낸다. 비공개 원문/평가 정답/검토 참고표를 보내지 않는다. 정정/전언/출처 중복·동일인/시각 오차·검사 충돌의 검토를 요청하는 구조화 프롬프트와 결과 계약이다. 이러한 관계의 의미 판단은 모델에 의존한다.

모델이 제안한 인용은 공개 자료의 정확한 연속 구간이어야 한다. 관측/충돌/가설/확인 요청에 인용이 없거나 범위 밖 ID/틀린 구간/추가 권한 필드가 있으면 출력 전체를 무효로 처리한다. 단순 키워드 단정 차단은 모든 표현/언어의 의미적 안전성을 보장하지 않는다. 시간 계산도 모델이 추출한 입력을 가정한 계산이며 신원·시각 추출의 정확성은 별도 검수한다. 사람이 외부 조사를 수행한 것처럼 기록하지 않는다.

INSUFFICIENT는 유효한 검토 뒤 보류한 결과와 실행 실패 시 대체 결과 모두에 쓰일 수 있다. 후자는 PARTIAL과 validation_notes, 리뷰 INVALID/BUDGET_BLOCKED로 분리하고 실패를 사건 자체의 증거 부족으로 표시하지 않는다. 공개 자료가0개면 모델 호출0으로 NO_EVIDENCE다. 원문을 조용히 자르지 않으며 예산 초과는 보류한다. 취소/전역 시간 초과는 기존 작업 계약을 따르며 완료하지 못한 모델 해석을 보장하지 않는다.
