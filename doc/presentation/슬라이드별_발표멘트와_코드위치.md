## 시연 준비와 전환 순서

1. 에디터에 `server.py`, `agent/graph.py`, `agent/investigation.py`, `agent/validation.py`를 미리 연다. 위 표의 시작 행에 북마크를 둔다.
2. 슬라이드 2·3·4·6은 PPT의 코드 발췌로 설명해도 된다. 실제 에디터를 보여줄 때는 각 슬라이드의 우선 코드 한 곳만 짚고 돌아온다.
3. 슬라이드 5는 저장된 실제 모델 실행 결과를 재구성한 수치 비교로 설명한다. `payments-service`, CPU 91%, 배치 기여 5%, 요청 처리 기여 88%, 요청량 3.2배를 차례로 짚는다.
4. 실시간 입력 거절을 보여주려면 슬라이드 2 시간 안에서 `오늘 날씨 알려줘` 한 건만 제출한다. 발표 전에 `bash sh/run_live.sh`로 연결을 준비한다. 발표 시간이 부족하면 PPT 코드만 설명한다.
5. 전체 조사·Judge 재평가는 발표 중 실행하지 않는다. 모델 호출 대기 대신 저장된 결과와 원본 기록을 보여준다.

## 질문 대비

- 실제 검증 모델은 계획·작성에 Ollama `qwen3.5:2b`, 별도 Judge에 `qwen3:8b`다. OpenAI는 설정으로 지원하지만 보존된 실측에는 사용하지 않았다.
- 지표·로그·추가 관측은 합성 데이터다. 추가 조사는 CPU 80% 이상 인시던트의 세 가설·네 관측 종류이며 상세 관측은 `payments-service`에 제공한다.
- 0토큰은 차단한 요청의 생성 입력·출력 사용량이다. 전체 비용 절감률과 로컬 하드웨어 비용은 측정하지 않았다.
- Judge는 별도 평가 경로다. 코드가 수치·출처·조치 조건을 검증하고 가설 상태를 판정한다. 모순 감지로 점수 상한을 적용해도 원래 점수를 보존한다.
- 기능 6/6과 종합 5/6을 구분한다. release의 Judge 오판과 최초 전체 평가의 미탐지를 기록에 남겼다.
- SQLite는 완료 결과와 후속 질문 맥락을 복원한다. 실행 중 LangGraph 체크포인트 재개는 지원하지 않는다.
- 역할별 전문 서브그래프가 수집과 검색을 담당하고 LLM은 질문 선택·보고서 작성에 사용한다. 벡터 저장과 검색은 SQLite·NumPy로 구현했다.
